# DesktopPets

[中文](README.md) | English

A small macOS desktop pet: a borderless, always-on-top sprite that wanders along the bottom of
your screen, can be dragged around, and talks in a little speech bubble.

## Quick start

```sh
./Scripts/make-placeholder-skin.sh   # generate a placeholder critter (skip if you have your own art)
./Scripts/pack-skins.sh              # pack loose frames into a sprite sheet + GIF previews
swift run DesktopPets                # run it
```

## Controls

| Action | What it does |
| --- | --- |
| **Left click** | Opens the menu at the pointer: speak toggle, switch language, reload, reset position, quit |
| **Left drag** | Moves the pet. On release it is pulled back on screen and its position is remembered |
| **Right click** | Opens the **skin picker** — switch model or version |
| **Menu-bar icon** (🐾) | All of the above, always reachable |

The menu language follows your system language until you toggle it (`zh*` → Chinese, otherwise
English), and your choice is remembered. The language toggle lives in the left-click menu (and the
menu-bar item); right-click was given to the skin picker.

**Switching language changes both the menu and what the pet says** — there is one phrase file per
language, see below.

### Why there is also a menu-bar icon

Every control the pet has hangs off a **sprite you have to click**, which is a single point of
failure: if the pet is covered, off-screen, or not receiving clicks, there is no way to quit it. The
menu-bar item does not depend on the pet's window, is the standard configuration for an
`.accessory` app, and exists specifically to make "I cannot close it" impossible.

### The menu is self-drawn, and does not steal focus

It uses `.nonactivatingPanel`: it takes clicks **without** bringing this app forward, so typing in
whatever you were using is not interrupted when the menu opens.

The trade-off is that **Escape does not close it** — receiving key events would mean becoming key,
which is exactly the focus stealing this avoids. It closes when you pick an item, click outside it,
or after 30 seconds of no activity.

## Diagnosing "I cannot click the pet"

Whether the pet is clickable depends entirely on the alpha of the pixel under the cursor, and that
is invisible from outside the process — so the relevant state goes to the system log. Start here:

```sh
log stream --predicate 'subsystem == "com.desktoppets.DesktopPets"'
```

You will see `click-through ON/OFF` flip as the cursor enters and leaves the pet:

- `ON — cursor outside window` → the cursor is not over the pet's window
- `ON — alpha 0 vs threshold 16` → inside the window, but that pixel is transparent (normal;
  clicks pass through to whatever is behind)
- `OFF — forced interactive (dragging)` → events are forced on for the duration of a drag
- `ON — no alpha mask available` → **a real fault**: no decoded frame, so the pet is entirely
  unclickable

`mouseDown at ...` prints whenever the pet is pressed, which confirms whether clicks are reaching
the window at all.

To build a double-clickable app:

```sh
./Scripts/build-app.sh               # -> dist/DesktopPets.app
```

## Supplying your own art

Create `Resources/Skins/<name>/` with this layout:

```
Resources/Skins/mypet/
  skin.json                        # hand-written: fps, loop, scale, anchor, hit threshold
  src/                             # hand-drawn frames, one directory per state
    idle/000.png 001.png 002.png 003.png
    walk/000.png ... 005.png
    drag/000.png ... 003.png
    sleep/000.png ... 003.png
    click/000.png ... 005.png      # click is the one non-looping state
  build/                           # generated by the packer — do not edit
  preview/                         # generated GIFs, for checking rhythm by eye
```

## Placing art for several models and versions

### The one rule

The app scans `Resources/Skins/` and **a directory only counts as a skin if it contains a
`skin.json`** — either at the top level, or one level below it.

That single rule is what lets a directory exist purely for grouping: a folder without a `skin.json`
is never mistaken for a skin.

### Four layouts

**1. A single character** — the menu shows `mypet`

```
Resources/Skins/
  mypet/
    skin.json
    src/idle/000.png ...
```

**2. Several characters (siblings)** — the menu shows `bird`, `cat`, `dog` (alphabetical)

```
Resources/Skins/
  cat/   { skin.json, src/ }
  dog/   { skin.json, src/ }
  bird/  { skin.json, src/ }
```

**3. Versions of one character (a group)** — the menu shows `cat/v1`, `cat/v2`

```
Resources/Skins/
  cat/
    v1/            { skin.json, src/ }
    v2/            { skin.json, src/ }
    reference/     <- no skin.json, so not a skin
      turnaround.png
```

**4. Both a skin and a group** — the menu shows `cat`, `cat/v1`, `cat/v2`

```
Resources/Skins/
  cat/
    skin.json      <- cat is itself a usable skin
    src/
    v1/  { skin.json, src/ }
    v2/  { skin.json, src/ }
```

### Things worth knowing

- **Only one level is walked.** `cat/v1/final/` is not discovered — deliberately, so identifiers
  stay short enough to read in a menu.
- **`build/` and `preview/` are always excluded**, even though the packer writes a `skin.json` into
  `build/`. Without that exclusion it would show up as a skin of its own.
- **The menu shows the directory path** (`cat/v1`), not the `name` field in `skin.json`. The name is
  the path, so there is nothing to keep in sync.
- **Each skin can have its own `frameSize` and `scale`.** Switching resizes the window to match; no
  code change needed.
- **Removing a skin is just deleting the directory**, then picking "Reload Skin and Phrases".

### Switching

**Right-click the pet** → the skin list appears with the current one ticked. Picking one switches
immediately, no restart.

Switching re-reads the manifest, the frames and the phrases, and resizes the window to the new
frame size. The pet's position is kept. The menu-bar 🐾 item carries the same list.

### Two worked examples ship with the repo

| Identifier | Location | What it is |
| --- | --- | --- |
| `placeholder` | `Resources/Skins/placeholder/` | top-level skin, ginger |
| `placeholder/grey` | `Resources/Skins/placeholder/grey/` | a **nested variant** of the same character, grey |

The framing is identical between them and only the palette differs, so a switch is obvious at a
glance. `Scripts/make-placeholder-skin.sh` regenerates both.

Rules the loader enforces:

- **Filenames sort into play order**, so zero-pad them (`000.png`, not `0.png`).
- **Every frame in a skin must be the same size**, matching `frameSize` in `skin.json`.
- **Frames must have transparent backgrounds.** Transparent pixels are what makes clicks pass
  through to whatever is behind the pet.
- `idle` and `walk` are required. `drag`, `sleep` and `click` are optional; if you leave one out,
  the pet falls back to `idle` for it.
- **Unknown state names are rejected**, so a typo like `sllep` fails loudly instead of silently
  doing nothing.
- To skip a state entirely, delete its `skin.json` entry *and* its `src/` directory. The packer is
  stricter than the app and requires frames for every declared state.

`skin.json`:

```json
{
  "name": "mypet",
  "frameSize": { "width": 64, "height": 64 },
  "scale": 2,
  "anchor": "bottomCenter",
  "hitAlphaThreshold": 16,
  "states": {
    "idle":  { "fps": 6,  "loop": true },
    "walk":  { "fps": 10, "loop": true },
    "drag":  { "fps": 8,  "loop": true },
    "sleep": { "fps": 3,  "loop": true },
    "click": { "fps": 12, "loop": false }
  }
}
```

`scale` is the display multiplier: a 64x64 frame at `scale: 2` is drawn 128x128 points, so draw at
2x for a crisp result on a Retina display. `anchor` is which point of the sprite follows the mouse
and gets remembered (`bottomCenter` means the feet). `hitAlphaThreshold` is the alpha at or above
which a pixel counts as clickable.

`row` and `frames` are **not** written by hand — the packer fills them in and writes
`build/skin.json`.

### Phrase files (one per language)

```
Resources/Phrases/
  zh.json     Chinese lines
  en.json     English lines
```

**The filename is the language code**, and the pet's lines follow the menu language — switch to
English and the menu and the lines change together. (Otherwise you get an English menu over a pet
still speaking Chinese.)

Each file is a flat object of category to phrases:

```json
{
  "click": ["Hey, stop poking me!"],
  "idle":  ["Nice weather today."],
  "drag":  ["Put me down!"],
  "sleep": ["Zzz..."]
}
```

- A missing category falls back to `idle`
- **A missing language file** means the pet stays quiet in that language; the app still runs
- **A malformed file** silences the pet and logs the error; it does not crash
- To add a third language: add a case to `AppLanguage`, a `MenuStrings` entry, and a `<code>.json`

## Commands

| Command | What it does |
| --- | --- |
| `swift run DesktopPets` | Run from source. Resolves art from `Resources/` in the repo. |
| `./Scripts/test.sh` | Run the unit tests. |
| `./Scripts/make-placeholder-skin.sh` | Regenerate the placeholder skin. |
| `./Scripts/pack-skins.sh [name ...]` | Pack loose frames into a sheet plus GIF previews. |
| `./Scripts/build-app.sh` | Build and ad-hoc sign `dist/DesktopPets.app`. |
| `swift run DesktopPets --verify-skin` | Headless check: load the skin and phrases, print a summary, exit. |

`--verify-skin` is the fastest way to check new art without launching a window. It is also the
smoke test `build-app.sh` runs against the bundle.

`pack-skins.sh` re-reads the sheet it just wrote and compares every frame against the source PNG
byte for byte. If the row, column or vertical-flip maths were wrong, the sheet would still *look*
plausible — comparing pixels is the only honest check.

## How it fits together

```
Sources/
  DesktopPetsCore/     pure logic: manifests, layout, walking, animation timing, state machine,
                       phrase picking, config, asset lookup. No AppKit, so it all unit tests
                       without a window server.
  DesktopPets/         the AppKit shell: window, sprite drawing, mouse handling, speech bubble.
  SkinPacker/          build-time art tool. Not shipped in the bundle.
Resources/             runtime content, copied wholesale into the .app
Packaging/Info.plist   bundle metadata (LSUIElement, so there is no Dock icon)
```

`Resources/` is deliberately **not** declared as SPM bundle resources. It is runtime content:
adding a skin never touches `Package.swift`, and `build-app.sh` copies the directory as-is.
`AssetLocator` finds it in three tiers — `DESKTOPPETS_RESOURCES` override, then
`Bundle.main.resourceURL` for a built `.app`, then the source tree for `swift run`.

## Notes and limitations

- **Click-through is polled, not event-driven.** The 30Hz tick that drives the animation also
  samples the sprite's alpha under the cursor and toggles `ignoresMouseEvents`. That avoids global
  event monitors (and their permission and focus subtleties) at the cost of up to ~33ms before a
  click starts passing through. `MousePassthrough` is the only place to change if that ever
  matters.
- **While the menu panel is open it installs a global mouse monitor** (mouse only — this needs no
  accessibility permission) so that clicking elsewhere dismisses it. Nothing is installed while the
  menu is closed.
- **Escape does not close the menu**, for the focus reason explained above.
- **The app is ad-hoc signed.** It runs on the machine that built it. Copying it elsewhere hits
  Gatekeeper; distributing it would need a developer certificate and `notarytool`.
- **macOS 14 is the floor**, because the Swift Testing framework bundled with the toolchain is
  built against 14.0.
- **The tests need a plugin path.** If CommandLineTools is the active developer directory, SwiftPM
  does not pass `-plugin-path` for the Swift Testing macro plugin, and `@Test` fails to expand with
  "plugin for module 'TestingMacros' not found". `Package.swift` and `Scripts/test.sh` both derive
  and pass it; use the script if bare `swift test` ever misbehaves.

### Testing gotcha

Swift Testing captures each side of a comparison independently. Comparing a `CGFloat` against a
*compound* expression —

```swift
#expect(clamped.y == -200 + 1080 - 64)   // false, even though both sides are 816
```

— infers `Int` for the right-hand side and compares unequal. Bare literals are fine. Always compare
against a typed value:

```swift
let expected: CGFloat = 816
#expect(clamped.y == expected)
```
